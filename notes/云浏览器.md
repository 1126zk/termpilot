# 云浏览器

## 目标

给服务器上的开发会话加一个无头浏览器：Agent 可以直接查看和操作页面，人不用另开本地浏览器，在 TermPilot 里就能看到同一个浏览器会话。

核心用途是方便开发，不是提供公网浏览服务，也不是传输完整的 Linux 桌面。

场景是云开发：用户买云服务器，Kimi、pi 等 Agent 直接跑在服务器上做开发（不是本机通过 MCP 控制 TermPilot 的那种）。TermPilot 负责在服务器上把浏览器拉起来，Agent 和人共用这个浏览器。

## 使用形态

- 入口放在顶栏，仅 SSH 服务器和 WSL 会话显示。
- 启动后左边保留终端，右边显示浏览器画面。
- 有浏览器画面时隐藏运维面板、文件标签栏和右侧边栏，把空间留给终端和页面。
- 云浏览器归属于服务器会话，不放进运维面板的网站管理。
- 同一台服务器的 Agent 和人连接同一个浏览器页面，看到同一会话。

## 已确定的方案

- 服务器用 Docker 运行支持无头模式和 CDP 的 Chromium 镜像，不安装 XFCE，不使用 VNC、RDP 或 noVNC。
- 预览页直接通过 CDP 接收 `Page.startScreencast` 返回的画面并展示，鼠标键盘操作也通过 CDP 回传，服务器端不额外运行 Web 预览服务。
- CDP 通过 SSH 隧道连接，不暴露到公网。
- 开发服务和浏览器在同一台服务器时，Linux 下优先让浏览器容器使用 Host 网络，直接访问服务器上的 `127.0.0.1:端口`。
- 初版不自建镜像，也没有开发机：直接拉公共 Chromium 镜像（候选 `chromedp/headless-shell`，纯 headless、原生支持 CDP 和 screencast），服务器零构建、不装开发环境，不引入 Compose。
- 只有将来确需定制镜像（预装插件、改默认配置等）时，才在本地或 CI 构建并推 registry，原则不变：服务器永远只拉取和运行。
- 安装、启动和卸载由 TermPilot 一键完成；镜像和浏览器数据是否清理由用户选择。
- Agent 直连 CDP，不做 MCP 封装：容器调试端口绑服务器 127.0.0.1，跑在服务器上的 Agent 直接 ws 连接，TermPilot 不替 Agent 提供工具层。多个 CDP 客户端连同一浏览器是原生支持的，与人的预览互不挤占。
- TermPilot 只负责两件事：容器生命周期（安装、启动、停止、卸载）和本地预览链路（SSH 隧道 + CDP screencast 画面 + 输入回传）。

## 当前状态

目前只有静态界面原型：

- 顶栏新增云浏览器按钮，按 SSH、WSL 会话显示。
- 点击后终端与静态浏览器画面左右分屏。
- 静态画面包含浏览器工具栏、地址栏和开发服务示例页面。
- 关闭预览后恢复此前的运维面板、文件和右侧栏状态。
- 尚未连接 Docker、CDP、端口映射或真实浏览器，安装和卸载也未实现。
- `npm run build` 已通过；实际点击效果仍需人工确认。

## 后续接入

1. 确定 Chromium 镜像、启动参数和容器命名。
2. 通过现有 SSH 执行能力实现检测、安装、启动、停止和卸载。
3. 建立到 CDP 的 SSH 隧道，处理连接状态和断线重连。
4. 将右侧静态画面替换为 CDP Screencast，并接入输入回传。
5. 让 Agent 与预览页连接同一浏览器目标，验证开发服务访问和协同操作。
