# 展示页

GitHub Pages 上的发布页：下载、软件截图、功能介绍、MCP 用法、更新记录。地址 https://1126zk.github.io/termpilot/ 。

## 发布方式

用 main 分支的 `docs/` 原样发布，不打 tag、不走 Actions，也和 `release.yml` 无关。

- 第一次：仓库先公开（免费账号的私有仓库开不了 Pages），再到 Settings → Pages → Deploy from a branch → `main` + `/docs`。也可以 `gh api -X POST repos/1126zk/termpilot/pages -f "source[branch]=main" -f "source[path]=/docs"`。
- 之后改 `docs/` 推到 main，GitHub 自带的 "pages build and deployment" 一两分钟后自动发布。
- `docs/.nojekyll` 是空文件，让 GitHub 跳过 Jekyll 原样发布，别删。
- `docs/` 只放页面：`index.html`、`icon.png`、`shots/*.webp`。笔记放 `notes/`。

## 页面结构（`docs/index.html`，单文件，无依赖）

从上到下：

1. **顶部**：左边图标、版本号、日期、大下载按钮；右边三个平台的紧凑列表。
2. **主截图**：四个标签切换——主机 / 工具 / 运维面板 / 侧边栏。
3. **运维面板**：左列表右大图，悬停或点击换图。资源和进程（默认选中，复用 `ops.webp`）、Docker、网站与反代、脚本与定时任务、手册。
4. **终端与侧边栏**：同上但左右镜像（`.features.flip`）。多窗口、标签分栏、标签内分栏、文件目录、Alt+V 粘贴图片、常用命令和历史、切换主题。「多窗口」没有真图，是两张截图错开叠放（`.stack`）。
5. **交给 AI 操作（MCP）**：三步用法（左步骤右截图，同样悬停换图）+ 六张能力卡片。卡片文字来自 `internal/mcpx/catalog.go` 的工具描述，改工具后对一下。
6. **更新记录**：版本卡片，最新一版展开，其余折叠显示「N 项新功能 · M 项修复」。
7. **结尾一段话**：主要在 Windows 上用和测，其他平台欢迎 fork。

配色沿用软件默认主题 termius-dark（底 `#141729`、绿 `#21b568`）。固定 1440 左右的桌面宽度设计，**不做手机布局**。

### 运行时数据

页面加载时请求 GitHub API（未登录，每 IP 每小时 60 次）：

- `GET /repos/1126zk/termpilot/releases?per_page=6`：最新版本号、日期、三个包的直链和大小。按文件名后缀匹配：`-windows.zip`、`-darwin.zip`、`-linux.tar.gz`，和 `release.yml` 打包步骤的命名一致，改那边要同步改这边。
- `GET /compare/<上一版>...<这一版>`：两版之间的提交，按 `feat:` / `fix:` 前缀归类，`chore` 等不显示。所以**提交信息的前缀直接决定更新记录的内容**。

接口失败时（仓库私有、限流、断网）：下载按钮保持指向 `releases/latest` 页面，更新记录只剩标题和「全部版本 →」。这是有意保留的退路，不要改成隐藏。

想让下载按钮不依赖接口，可以把发版文件名去掉版本号，页面写死 `releases/latest/download/TermPilot-windows.zip`。讨论过，暂不做。

### 本地预览

直接用浏览器打开 `docs/index.html` 即可。仓库私有时接口会 404，看到的是退路状态；要看有数据的样子，用下文的 Puppeteer 拦截 `api.github.com` 返回模拟数据（拿本地 `git tag` 和 `git log A..B --format=%s` 拼）。

## 截图怎么做

原则：**截软件真实界面，不另画一套**。做法是把前端原样打包一份，后端换成内存假数据，用无头浏览器操作并截图。

### 1. 假后端

前端所有后端调用都走 `window.go.app.Bridge.Invoke(channel, args)`，事件走 `window.runtime.EventsOn(name, cb)`（见 `frontend/src/wails-api.ts`）。假后端就是在 `main.tsx` 之前把这两个对象装好：

- `Invoke` 按通道名查一张 handler 表，没模拟的通道返回 `null` 并 `console.warn('[demo] 未模拟的通道', channel)`，截图脚本把这些警告打出来，缺什么补什么。
- 终端：`term:create` 先发 `term:status` connecting，几百毫秒后发 connected 和欢迎语；输出走 `term:data` 事件，**payload 的 data 是 base64**。`term:bind-view` 之前的输出要先攒着，绑定后再一次推出去（和 Go 侧 `BindView` 行为一致），否则开头几行会丢。
- 简易 shell：回显、退格、回车执行 `ls`/`cd`/`cat`/`tail`/`docker ps`/`df` 等几条，提示符带颜色；每条命令发 `history:changed` 让历史面板有数据。
- 运维面板：`session:metrics`、`session:server-info`、`session:docker`、`session:web`、`session:cron-list`。脚本库存在 localStorage（`termpilot.scripts` 共享、`termpilot.scripts.<sessionId>` 单机），截图前用 `page.evaluateOnNewDocument` 预先写进去。
- 侧边栏：`sftp:list` / `sftp:read` 用一个内存文件树；剪贴板图片面板读 `~/.termpilot/paste`，`sftp:read-image` 返回任意 PNG 的 base64。
- MCP 设置页：`mcp:get`（enabled、port、token）、`mcp:state`（running、clients）、`mcp:audit`。
- 数据一律用假的：IP 用文档专用网段 `203.0.113.x` / `198.51.100.x`，域名 `example.com`，镜像 `ghcr.io/example/...`。

### 2. 构建（假后端不进仓库）

假后端和构建配置放在**仓库外**的临时目录，构建时临时拷进 `frontend`，构建完用 `trap ... EXIT` 无论成败都删掉，保证 `frontend` 不留东西：

- `frontend/src/demo/`：假后端 + `main.ts`（`import './backend'` 再 `import '../main'`）
- `frontend/demo.html`：复制 `index.html`，入口改成 `/src/demo/main.ts`
- `frontend/vite.demo.config.ts`：`mergeConfig` 继承 `vite.config.ts`，`__PLATFORM__` 固定 `win32`，`outDir` 指到仓库外，构建完把 `demo.html` 改名成 `index.html`

`npx tsc --noEmit -p . && npx vite build -c vite.demo.config.ts`，约 50 秒，产物约 30MB（Monaco、Mermaid 都在里面）。产物用 `npx http-server <目录> -p <端口>` 起服务。

### 3. 截图

Puppeteer（`puppeteer-core@23.11.1`，装在仓库外的临时目录）驱动本机 Edge：`C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe`。

- 视口 1280×760，`deviceScaleFactor: 2`，截出来 2560×1520，页面上缩小显示也清楚。
- 启动参数加 `--disable-webgl --disable-3d-apis`。**无头 Edge 下 xterm 的 WebGL 渲染会画坏**（字被放大、只剩一行）；关掉后 xterm 退回 DOM 渲染，效果和软件里一样。
- 步骤写成一串小指令：双击主机连接、点坐标开运维面板/侧边栏、键盘输入命令、右键标签、悬停菜单项，最后 `page.screenshot`，需要局部时用 `clip`。
- 右键菜单在整窗截图里太小：只截左上四分之一（`clip: 0,0,640,380`），比例不变，菜单放大一倍。

### 4. 压缩

PNG 一张两三百 KB，转成 WebP（质量 0.86）后大多 30–240KB。转换也用 Puppeteer：页面里 `new Image()` 载入 PNG，画到 canvas，`toDataURL('image/webp', 0.86)`。全部截图约 2.6MB。

## 踩过的坑

- **按文字找元素会先命中终端**：关掉 WebGL 后终端是 DOM，`::-p-text(shop)` 先匹配到终端里 `cd shop` 的字，点到的不是文件树。取最后一个匹配，或者先确定区域再找。
- **点两次等于没点**：文件树的目录点一下展开、再点折叠；上面那个误命中时容易出现。
- **提示条要等它消失**：如「密钥对已生成」，点完等 5 秒再截。
- **菜单高亮用方向键，别靠鼠标悬停**：右键菜单里用 `mouse.move` 悬停换项，高亮没跟着变，两张「不同菜单项」的截图逐字节相同，差点就这么提交了。改成右键后把鼠标挪出菜单，按 `ArrowDown` 逐项移动，再读 `[role=menuitem][data-highlighted]` 的文字确认高亮在哪。**截完一批图跑一次 `md5sum *.webp | sort | uniq -w32 -d`**，有输出就是有重复。
- **截 clip 要加滚动偏移**：`getBoundingClientRect()` 是视口坐标，`clip` 要文档坐标，加上 `scrollY`。
- **`python3` 是空壳**：这台机器上的 `python3` 是应用商店占位程序，什么都不执行也不报错，拿它改文件会静默失败。用 Node 或编辑工具。
- **heredoc 写脚本被拦**：Bash 里用 heredoc 生成脚本时被安全检查当成看不懂的删除命令拦下。脚本用文件工具写，再用 Bash 跑。
- **临时目录删不掉**：被 http-server 占用过的目录，停掉服务后仍提示 `Device or resource busy`，只能事后手动删。
- **只改外观就别改行为**：做更新记录美化时顺手把「接口失败就隐藏整块」加进去，结果「全部版本」链接也没了。改样式的需求只动样式。
- **界面上不写说明废话**：页面上的功能项只写标题，不写解释（MCP 部分是例外，那里本来就是用法说明）。
