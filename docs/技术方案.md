# TermPilot —— Agent 可操控的 SSH 终端 · 技术方案

> 当前版本只保留两种能力：**正向 SSH**（本机作为客户端连服务器，用户名+密码认证）和**本机终端**（node-pty）。
> Telnet、串口、反向监听（反弹 shell）、私钥认证和传输队列已从产品中移除；端口映射只保留本地/远程转发两种，IP 固定 127.0.0.1。
> 本文档与当前代码一致，不再保留历史选型调研。

---

## 1. 产品定位

一款类似 XShell 的桌面终端工具，同时内置 MCP Server：

- 人工图形化操作：SSH 连接管理、多标签终端、远程文件树（SFTP）、远程文件编辑器；
- AI Agent（Codex / Kimi Code / Claude Code 等）通过 MCP 直接控制同一套终端：执行命令、读写服务器、读取缓冲行、截图。

Agent 和人是两个平等的"客户端"，操作同一套主进程服务：Agent 打开的终端出现在标签栏，人可以直接接管；人的操作 Agent 也能读到。

## 2. 技术栈

| 层 | 依赖 | 用途 |
|----|------|------|
| 框架 | Electron + React 19 + TypeScript + electron-vite | main / preload / renderer 统一构建 |
| 终端渲染 | `@xterm/xterm` + addon-fit + addon-webgl | WebGL 渲染（GPU 加速），缓冲行读取给 MCP |
| SSH | `ssh2` | 连接、shell 通道、exec 通道、SFTP，密码认证，支持跳板（ssh -J） |
| 本地 PTY | `node-pty` | 本机终端（Windows PowerShell / POSIX shell）。原生模块，需匹配 Electron ABI，加载失败只影响本机终端 |
| 状态 | `zustand` | 渲染进程状态 |
| UI | tailwindcss + shadcn（radix-ui）+ lucide-react | 界面 |
| 存储 | Node 内置 `node:sqlite`（WAL） | `userData/termpilot.db`：会话、打开的窗口、主机备注、MCP 配置、审计日志 |
| 密钥 | Electron `safeStorage` | 密码 / 跳板口令 / MCP 令牌加密落盘，明文不返回渲染进程 |
| MCP | `@modelcontextprotocol/sdk` | 内置 MCP Server，Streamable HTTP |
| 打包 | electron-builder（NSIS / dmg / AppImage） | 安装包 |
| CLI | Go（`cli/` 目录） | `termpilot` 命令行，窗口外调 MCP 工具，窗口没开时先拉起应用 |

## 3. 总体架构

```
┌────────────────────────── Electron 主进程 (main) ──────────────────────────┐
│  StorageService   SshPool          TerminalService   SftpService           │
│  (sqlite+safeStorage, 会话CRUD) (ssh2 连接复用/心跳) (SSH shell + 本机 PTY) │
│  ExecService      McpService       AgentConfigService                      │
│  (独立 exec 通道)  (MCP Server + 工具目录 tool-catalog) (写入 Agent 配置)   │
└───────────────────────────────────▲────────────────────────────────────────┘
                                    │ 类型化 IPC（contextBridge 白名单 window.api）
┌───────────────────────────────────┴────────────────────────────────────────┐
│                          渲染进程 (renderer, React)                         │
│  侧边栏（连接树 + 远程文件树）  标签栏   终端视图 × N（xterm.js WebGL）      │
│  TerminalPool（进程级 xterm 单例，切换标签不丢缓冲）                         │
│  远程编辑器（Monaco）  设置弹窗   状态栏（连接状态 / MCP 状态）              │
└─────────────────────────────────────────────────────────────────────────────┘
```

**进程职责**：所有能力（SSH、PTY、SFTP、数据库、截图）只在主进程；渲染进程只做展示与交互，经 preload 白名单调用。MCP Server 与渲染进程平级，复用同一套主进程服务。

## 4. 核心模块

### 4.1 会话管理

- 会话模型：`{ id, publicId(conn- 编号), name, group, host, port, username, remark, jumpHost/jumpPort/jumpUsername, sshOptions, ... }`，认证只用密码
- 侧边栏连接树按主机分组（同主机的多条连接归在一台机器下，主机可写备注），顶部搜索过滤；右键菜单：打开 / 新开一扇终端 / 备注 / 编辑 / 删除 / 复制 Agent 提示词。
- 密码用 `safeStorage` 加密后入库；`hasSecret` 标记是否已存，密文绝不通过 IPC 返回界面。
- 每条正向连接与本机 `~/.ssh/config` 的具体 `Host` 对齐（`ssh-config-file.ts`）：改主机/端口/用户/跳板时同步写回配置文件；启动时把配置文件里的具体主机导入为连接，一律按密码会话导入。密码、备注不写入配置文件。带通配符的 `Host` 和 `Match` 不导入。

### 4.2 终端模块（TerminalPool 单例）

- xterm 实例不跟随 React 组件生命周期：每扇终端一个进程级 `Terminal` 实例挂在游离 host `<div>` 上，标签视图只做 re-parent，切换标签不丢缓冲、TUI 不白屏。
- WebGL 渲染，监听上下文丢失自动重建；FitAddon + ResizeObserver 把 `cols/rows` 同步到 ssh2 `setWindow()` / `pty.resize()`。
- 数据通道：主进程统一经 `TerminalService` 推送 `term:data` / `term:status`，上行 `term:input` / `term:resize`。
- 终端持久化：窗口编号、标题、备注和已画好的行存 sqlite，重启后按行写回，新会话从下一行开始；断开的终端用 `term_reconnect` 恢复，编号不变。

### 4.3 SSH 连接（SshPool / ExecService）

- `SshPool`：同一条连接复用一个 ssh2 Client，多扇终端共享，引用计数归零才断开；带心跳与半死连接重拨。
- 跳板（`ssh -J`）：优先走 `forwardOut` 转发；跳板禁止转发时在跳板里再登录一次（仅终端可用，文件树不可用）。
- `ExecService`：独立 exec 通道执行命令，不占终端画面，可并发；stdout/stderr 分流、协议级退出码；同名 session 跨调用承接 `cd` / `export`（远端 `~/.cache/termpilot/exec/` 下保存环境）。
- `TerminalService.execCommand`：在已打开的终端里跑命令（term_pty 用），用提示符回归判断跑完，POSIX shell 附带退出码探针。

#### 端口映射（forward.ts）

- 数据模型：`forwards: { type: 'local' | 'remote', listenPort, targetPort }[]`，sqlite 里存 JSON 字符串；IP 不进配置，监听和另一头都固定 127.0.0.1，用户只填端口。连接表单底部「添加端口映射」编辑，全空规则入库前丢弃。
- 连接建立后在共享 SSH 连接上只挂一次，连接关闭统一回收，重拨自动重挂；单条规则失败（端口被占）只记日志，不影响连接。
- local（`ssh -L`）：`net.createServer` 监听本机 127.0.0.1，接入 socket 用 `forwardOut` 开通道到服务器的目标端口，双向 pipe。
- remote（`ssh -R`）：`forwardIn` 让服务器 127.0.0.1 监听，`tcp connection` 事件里按 destPort 匹配后 accept，接回本机目标端口双向 pipe。

### 4.4 远程文件树与编辑器（SftpService）

- 侧边栏「文件」页显示当前选中连接的远程目录，VS Code 资源管理器式就地展开；支持打开目录、新建文件夹、上传、下载、重命名、删除。
- 远程文件可直接在 Monaco 编辑器里编辑保存。
- 目标机没有 SFTP 子系统时，提供远程安装引导（`resources/install-sftp.sh`），安装进度推送界面。
- SFTP 复用 SSH 连接，不另开端口；上传下载单文件限 512MB。

### 4.5 MCP Server（Agent 控制面）

- 监听 `http://127.0.0.1:<port>/mcp`（Streamable HTTP），只绑回环，强制 Bearer Token 鉴权；令牌在设置页生成/复制，可一键写入本机各 Agent 的 MCP 配置（`AgentConfigService`）。
- 工具目录（`tool-catalog.ts`，MCP 与 CLI 共用一份定义）：
  - 连接：`connection_list / open / close / create / update / delete`（只认 `conn-` 编号）
  - 终端：`term_list / exec / pty / write / read / reconnect / close / update / open_local`（`term-` 编号）
  - 画面：`term_lines`（带行号读缓冲）、`term_screenshot`、`term_screenshot_scrollback`（缓冲拼图长截图）
  - 文件：`sftp_list / mkdir / upload / download / rename / remove`
- 危险操作（`rm`、写系统路径、删除连接等）可弹窗等人确认后再执行；所有调用写审计日志（sqlite）。
- CLI（`cli/`，Go）：`termpilot tools / schema / call`，与 MCP 同一份工具定义；窗口没开时先拉起应用。

### 4.6 截图

- 普通截图：`webContents.capturePage(rect)` 截取终端区域。
- 长截图：从 xterm `buffer.active` 按行范围读取，离屏重渲染拼接成长图；设置里的「合成算法」打开时按缓冲拼图，不滚动正在看的画面。

### 4.7 安全模型

- `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`；preload 只暴露 `window.api` 白名单。
- MCP 只监听 `127.0.0.1`，校验 Host 头与 Bearer 令牌。
- 凭据一律 `safeStorage` 加密；截图只能保存在 userData/screenshots 下。

## 5. 界面布局

```
┌──────────────────────────────────────────────────────────────┐
│ 标签栏: [连接名 · 窗口 1] [本机终端 · 窗口 1]                  │
├──┬───────────────────────────────────────────────────────────┤
│侧│                                                           │
│边│                终端区域 (xterm.js WebGL)                   │
│栏│            或远程文件编辑器 (Monaco)                        │
│ ▾ 连接（正向 SSH，按主机分组）                                 │
│ ▾ 本机终端                                                    │
│ 页签：连接 | 文件（远程文件树）                                │
├──┴───────────────────────────────────────────────────────────┤
│ 状态栏: 连接状态 | MCP: 监听中/已连接 N                        │
└──────────────────────────────────────────────────────────────┘
```

- 侧边栏可整体收纳成图标栏；连接树节点折叠状态保留。
- 状态栏显示 MCP 运行状态，方便确认 Agent 是否接入。

## 7. 风险与对策

| 风险 | 说明 | 对策 |
|------|------|------|
| node-pty Windows 构建 | 原生模块需匹配 Electron ABI | `createRequire` 动态加载并兜底：失败时仅本机终端不可用，SSH 不受影响 |
| WebGL 上下文丢失 | GPU 驱动崩溃/休眠后黑屏 | 监听上下文丢失事件，重建 addon |
| 长截图内存 | 大缓冲拼图图片巨大 | 按行范围截取，超长分多张输出 |
| ssh2 大数据吞吐 | 刷屏时 IPC 压力 | 主进程侧截断保留尾部，渲染进程按视图订阅 |
| MCP 安全 | Agent 获得服务器控制权 | 仅回环监听 + Bearer 令牌 + 危险操作人工确认 + 审计日志 |
