# 运维面板

## 起因

有日常运维需求，看过几个方案都不满意：

- **1Panel 这类面板**：界面杂，功能远多于需要；而且要在服务器上常驻进程、多开一个 Web 端口。现在针对 agent 的网络攻击频繁，能不开的端口就不开。
- **TUI 程序**（最初想法是一个独立的二进制 TUI，直接展示内存、磁盘、进程）：终端环境五花八门，xshell、xterm、云厂商给的 tty 渲染各不相同，有的页面上字都看不清。TUI 的渲染依赖终端能力，这个问题绕不开。

## 结论

不装 agent、不开新端口、不做 TUI。直接在 TermPilot 桌面端做运维面板：

- 界面用桌面前端渲染，在哪都一致，不受终端差异影响。
- 数据全部走已有的 SSH 连接（执行命令、读 `/proc` 采集），服务器上什么都不留，攻击面就是本来就有的 SSH。
- 形态是"带监控的 SSH 客户端"：连着才有数据，断开就走，区别于 1Panel 那种常驻的面板服务器。
- 入口挂在标题栏，只支持 Linux：SSH 远程连接且探测到对端是 Linux 才出现。

## 核心目的

**是辅助操作的工作台，不是看板。**

- 面板里有命令输入区，是真正动手操作的地方。
- 可视化信息（CPU、内存、磁盘、进程）是为操作服务的：看一眼就知道机器什么状态、哪个进程在吃资源，决定要不要动手、对什么动手。
- 价值在于少敲重复命令：看负载不用 `top`，看磁盘不用 `df -h`，找吃内存的进程不用 `ps aux | sort`——这些一眼可见。真正要花精力的是那条要输入的命令。
- 信息区回答"要不要动手、对什么动手"，命令区负责"动手"。
